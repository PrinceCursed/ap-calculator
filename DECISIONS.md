# Принятые решения

Решения, которые я принял сам, без вопросов. Новые — сверху.

## 2026-11-10 · Обратная связь на реальных (коротких) логах

| Решение | Почему |
| --- | --- |
| Разбор оказался исправен: файл `samples/real-families-short.txt` (взят из `~/Downloads/logs.txt`: 50 строк, табы, CRLF, The Families, 09.11 23:36 – 10.11 00:27) разбирается полностью — 50 из 50 строк. 0 AP — правильный ответ: за 09.11 подходит только «Взламывает дом #137.» (1 из 30). Проблема была в том, что интерфейс ничего не объяснял. | Воспроизвёл прогоном через `loadFiles` и `analyze`, как в приложении. |
| Файла `samples/real-9-nov.txt` нет ни в проекте, ни на диске (искал через `mdfind` и `find` по домашней папке). Поэтому проверку «граффити, аирдроп, рэкет на реальном файле» сделать не удалось. Устойчивость парсера проверена на реальном файле, преобразованном во все форматы: одиночные пробелы, LF/CRLF, смесь разделителей, BOM, NBSP, дата без запятой, windows-1251. | Подменять реальные логи синтетикой для этой проверки было бы нечестно. |
| Колонка «Найдено в файле» показывает прогресс к порогу у каждого автоматического достижения: «1 из 30 домов», «0 из 3 побед», «2 грузовика из 3», «8 из 10 участников». У засчитанных — «найдено N строк». Для групп и последовательностей это лучшая найденная группа. | По ТЗ. Одна строка текста в движке (`progress.text`) используется и в таблице, и в тестах. |
| Строки с ненулевым прогрессом, но без зачёта помечаются янтарной точкой и попадают в «Спорные случаи» с теми же цифрами. Тест проверяет это для всех правил. | По ТЗ. |
| Предупреждение о неполном логе: покрытие меньше 20 часов (от первой до последней строки фракции за дату, включительно по минутам) или меньше 500 строк. Пороги — `COVERAGE_MIN_HOURS` и `COVERAGE_MIN_LINES` в `src/lib/pipeline.ts`. Если 30 не набрано — итог «0 / 30 AP (по неполному логу)». | По ТЗ. В реальном файле последняя строка за 09.11 — 23:55:29, а не 23:59, поэтому текст «23:36–23:55 (20 мин, 38 строк)». |
| Сводка «В файле: 09.11 — 38 строк, 10.11 — 12 строк» показывается, если у фракции больше одной даты. По клику — пересчёт за эту дату. Дата по умолчанию — с наибольшим числом строк. | По ТЗ. |
| «Диагностика разбора» свёрнута под результатом. В ней: всего / разобрано / не разобрано, примеры неразобранных строк, строки других фракций и дат, строки дня без подходящего достижения и 5 самых частых начал их текста (первые 3 слова), фракции (топ-10) и даты (топ-5) в файле, кодировка, если не UTF-8. | По ТЗ. «Без достижения» — строка не подходит ни под одну фразу ни одного правила. |
| Если для фракции и даты 0 строк — «В файле найдены: The Families (50 строк) …» с кнопками выбора фракции. Даты показаны текстом: при выбранной фракции без строк выбирать дату бессмысленно. | По ТЗ. |
| Кодировка: сначала UTF-8. Если заметная доля «�» (≥ 3 и ≥ 0,1 % символов) — пробуем windows-1251 и берём вариант с меньшим числом «�». | По ТЗ, без лишних срабатываний на случайный «�». |
| Дата и время в конце строки: запятая и пробел между ними необязательны. | По ТЗ. |
| Сутки — по дате, записанной в строке (`ДД.ММ.ГГГГ`). Внутренняя метка времени — «наивные» миллисекунды через `Date.UTC(год, месяц, день, …)`: это чистая арифметика, часовой пояс браузера не участвует, `new Date(строка)` нигде не используется. Тест проверяет границы 23:59:59 и 00:00:00. | ТЗ просило без сдвига часового пояса. Сдвига нет, а окна «за 60 / 90 минут до» по-прежнему корректно считаются через полночь. |

## 2026-11-10 · Дизайн по макету Claude Design

| Решение | Почему |
| --- | --- |
| Интерфейс сделан по макету `AP Screen v2` из архива «AP Calculator — обновлённый проект.zip»: цветовые токены тёмной и светлой темы, размеры (сайдбар 292 px, контент до 1160 px), радиусы (6 px у контролов, 8 px у панелей, 16 px у итога и зоны загрузки), Inter и JetBrains Mono. | Макет есть, а ТЗ требует «строго по макету». Общие правила из сообщения («радиус 8 px») действуют только когда макета нет, поэтому там, где они расходятся с макетом, приоритет у макета. |
| Иконки — `lucide-react`, толщина линии 1,5 как в макете. | ТЗ требует Lucide, а в макете пути иконок взяты из Lucide. |
| Эмблемы фракций — SVG из архива (`emblems/*.svg`), лежат в `public/factions/<slug>.svg`. Скачанные ранее с wiki превью `.webp` удалены. | ТЗ: «если файлы от меня есть — используй их». SVG проверены: скриптов и внешних ссылок в них нет. |
| В списке фракций короткие названия, как в макете («Русская», «National Guard»), в заголовке — полные («Русская Мафия», «LS Army»). Поле `short` в конфиге. | Так в макете, и длинные названия не обрезаются в узком сайдбаре. |
| Бейдж справа от фракции = AP фракции за выбранную дату (автоматические, с лимитом 30), появляется после загрузки логов. | В макете у фракций числа 0–30 — это шкала AP. Считается в том же Web Worker, на 50 000 строк добавляет миллисекунды. |
| Тема по умолчанию — тёмная, выбор хранится в `localStorage`. | Макет по умолчанию тёмный. |
| По умолчанию выбрана первая фракция Crime (The Ballas Gang), последняя выбранная запоминается. | В макете фракция выбрана всегда, и пустого состояния «выберите фракцию» нет. |
| Гос: вкладка и фракции видны, на месте — замок, подсказка при наведении «Правила для гос. структур ещё не добавлены» и маленький бейдж «Скоро» рядом с заголовком «ГОС. СТРУКТУРЫ». | Подсказка и замки — по макету. Бейджа «Скоро» в макете нет, но его требует исходное ТЗ, поэтому он добавлен минимально: одна плашка в строке заголовка. |
| Заблокированные фракции помечены `aria-disabled`, а не атрибутом `disabled`. | Атрибут `disabled` в Chrome глотает события мыши, и подсказка при наведении не показывалась. Клик всё равно игнорируется — это проверяется тестом. |
| В подвале результата, помимо строки из макета «Проигнорировано строк других фракций и дат», выводятся разбивка и «пропущено нераспознанных строк». | Счётчик пропущенных строк требует исходное ТЗ, а в макете под него нет отдельного места. |
| Строки-доказательства: номер, время, `Ник [статик]`, текст с подсветкой фразы. Зелёная подсветка в достижениях, янтарная в спорных случаях. Больше 200 строк — кнопка «… ещё N строк». | Формат строк по макету. Ограничение нужно, чтобы десятки тысяч строк не тормозили DOM. |
| Кнопка «Отменить» во время обработки останавливает Web Worker и создаёт новый. | Так в макете. Перезапуск воркера — единственный надёжный способ прервать синхронный разбор. |
| Мобильная версия (< 700 px) — как в макете: сверху бренд, кнопка темы и кнопка-меню с текущей фракцией, список фракций открывается выпадающей панелью. Горизонтальной прокрутки нет (проверено на 390 px). | По макету. |
| В репозиторий положена папка `design/` (макеты `.dc.html`, `support.js`, эмблемы). Скриншоты-референсы `uploads/` не добавлены. | Чтобы при будущих правках было с чем сверяться. Референсы — скриншоты чужих приложений, им не место в публичном репозитории. |
| В итоге не выводится строка «Автоматические · Ручные · Корректировка». | Её нет в макете, разбивку видно на вкладках. |

## 2026-11-10 · Алиасы и логотипы

| Решение | Почему |
| --- | --- |
| Ключ фракции = слаг логотипа (`yak`, `saspa`, `gov`, `army` …). | Один ключ вместо двух. |
| Алиасы: LS Army = National Guard = NG, Medical Services = Emergency Medical Service = EMS, Федеральная тюрьма = SASPA, Мэрия ЛС = Government, The Ballas Gang = East Side Ballas = Ballas, мафии без учёта регистра. | По ТЗ. Тест проверяет, что один алиас не принадлежит двум фракциям. |
| Если картинки нет или она битая — монограмма из 2 букв. | По ТЗ. Сборка от картинок не зависит. |

## 2026-11-09 · Первая версия

| Решение | Почему |
| --- | --- |
| Реальных логов в архивах не было — в `samples/sample-ballas.txt` лежит синтетический лог (генератор `scripts/make-sample.ts`), покрывающий все правила и мусор Discord. | Без примеров нечем проверить сценарий целиком. |
| «Доставка 189 ящ. → спорный случай» в ТЗ противоречит порогу ≥ 125. Реализовано по порогу: 189 ящ. спорно только при недоборе участников. | Порог — в конфиге (`train.final.minNumber`), его легко поменять. |
| PvP: группа «вывозит хаммер…» с паузами ≤ 60 мин = одно мероприятие, каждое «занимает 1 место» — отдельное. | Допущение из ТЗ, вынесено в конфиг. |
| Одна ЭМИ-строка подтверждает только одну атаку ФЗ. | Иначе одна ЭМИ превращала бы в ФЗ все атаки за час. |
| Группы относятся к дню своей первой строки, sequence — к дню финальной. Окна «до» смотрят и в предыдущие сутки. | Атаки, начатые до полуночи, не теряются. |
| Одинаковые строки из повторно загруженного файла не удваиваются. | Защита от двойного начисления. |
| Репозиторий публичный. | GitHub Pages бесплатно работает только с публичными репозиториями. Логов в репозитории нет. |
| Свой домен: переменная репозитория `VITE_BASE=/` + Custom domain в Settings → Pages (см. README). | Код при этом не меняется. |
