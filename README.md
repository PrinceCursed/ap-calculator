# AP Calculator

Калькулятор Activity Points (AP) для фракций GTA 5 RP. Администратор выбирает фракцию, загружает `.txt`-логи,
выбирает дату — сайт сам разбирает строки, начисляет AP за автоматические достижения, показывает
доказательства из логов, спорные случаи и ручные достижения. Лимит — 30 AP на фракцию в день.

**Всё считается в браузере.** Бэкенда нет, логи никуда не отправляются. Разбор и расчёт идут в Web Worker,
поэтому интерфейс не зависает даже на десятках тысяч строк (50 000 строк ≈ 0,1–0,3 с).

Сайт: https://princecursed.github.io/ap-calculator/

## Запуск локально

```bash
npm install
npm run dev      # http://localhost:5173/ap-calculator/
npm test         # юнит-тесты (Vitest)
npm run build    # сборка в dist/
```

## Как пользоваться

1. Слева выберите группу (Crime) и фракцию.
2. Загрузите один или несколько `.txt`-файлов (кнопкой или перетаскиванием). Повторно загруженные строки не удваиваются.
3. Дата выбирается автоматически (самая частая для фракции), её можно поменять — пересчёт мгновенный, файл заново не читается.
4. Клик по строке достижения раскрывает строки логов-доказательства (по шагам, с подсветкой фраз).
   Блок «Спорные случаи» показывает то, что было похоже на достижение, но не прошло условие.
5. Ручные достижения отмечаются галочкой / счётчиком `−`/`+`, внизу — общая корректировка «+/− AP».

## Как менять баллы, пороги и фразы

Все правила лежат в конфиге, код парсера трогать не нужно:

| Файл | Что там |
| --- | --- |
| `src/config/crime.ts` | фракции группы Crime (с алиасами) и все правила достижений |
| `src/config/gov.ts` | группа «Гос» (сейчас заблокирована) |
| `src/config/types.ts` | описание всех полей правил |

Каждое правило — объект с полями `id`, `title`, `points` (баллы за единицу), `phrases` и параметрами своего типа.
Примеры правок:

```ts
// Поменять баллы: «Поезд» теперь 4 AP
{ type: 'sequence', id: 'train', title: 'Поезд', points: 4, ... }

// Поменять порог: дома считаются по 25, а не по 30
{ type: 'perCount', id: 'houses', per: 25, ... }

// Добавить вариант фразы (достаточно совпадения любой)
phrases: ['грабит человека', 'ограбил игрока'],

// Засчитывать не чаще раза в день
oncePerDay: true,
```

**Фразы** сравниваются без учёта регистра, «ё» = «е», ищутся как подстрока текста события. Плейсхолдеры:

- `{n}` — число (для тиров и числовых условий): `'разгружает {n} материалов из оружейного магазина'`
- `{key}` — значение без пробелов, по нему считаются «разные» (номер ArmyNN/EMSnn, статик освобождённого)
- `{*}` — любой текст
- `re:...` — если нужна полноценная регулярка (именованные группы `(?<n>…)`, `(?<key>…)`).

`excludePhrases` — строки с такими фразами не считаются. `actor: 'player' | 'system'` — учитывать только
строки игроков или только `SYSTEM [1]`.

**Алиасы фракций** — поле `aliases` у фракции. Регистр, «ё», кавычки и лишние пробелы игнорируются.

**Лимит в день** — `dailyCap` у группы.

### Типы правил

| Тип | Как считает |
| --- | --- |
| `perLine` | каждая подходящая строка = событие; с `tiers` — баллы по числу `{n}`, берётся высший подходящий тир, каждый тир — отдельная строка таблицы |
| `perCount` | `floor(n / per) * points`; остаток (`n % per > 0`) — спорный случай «n из per» |
| `cluster` | строки группируются по времени (новая группа, если пауза > `gapMinutes`); группа с ≥ `minDistinct` уникальных значений (`distinctBy: 'static' | 'key'`) = одно событие. `soloPhrases` — строки, каждая из которых сама по себе событие |
| `sequence` | шаг 1 (≥ `minDistinct` уникальных статиков не раньше `windowMinutes` до финала, строго раньше финала) → финальная строка (опц. `minNumber`). Каждая финальная строка — одно событие; участники засчитанного события повторно не используются |
| `variantCluster` | как `cluster`, но тип события (вариант) выбирается по наличию предшествующей строки (`requiresPreceding`) — ФЗ против NG |
| `manual` | ручное достижение — только переключатель/счётчик в интерфейсе |

## Как добавить достижения для «Гос»

1. Открыть `src/config/gov.ts`.
2. Заполнить `rules: [...]` — в том же формате, что в `src/config/crime.ts` (можно копировать правила оттуда).
3. Поставить `enabled: true`.

Больше ничего править не нужно: вкладка «Гос» разблокируется, фракции станут доступны для выбора и расчёта.
Тест `tests/gov.test.tsx` проверяет и блокировку, и то, что одного флага достаточно для разблокировки.

## Деплой (GitHub Pages)

Каждый push в `main` запускает `.github/workflows/deploy.yml`: тесты → сборка → публикация на GitHub Pages.
`base` для Vite задаётся переменной `VITE_BASE` (по умолчанию `/<имя-репозитория>/`), поэтому при
переименовании репозитория ничего менять не нужно.

### Как подключить свой домен (CNAME)

1. У регистратора домена добавьте DNS-запись:
   - для поддомена (`ap.example.com`): `CNAME` → `princecursed.github.io`
   - для корневого домена (`example.com`): четыре `A`-записи на `185.199.108.153`, `185.199.109.153`,
     `185.199.110.153`, `185.199.111.153` (и при желании `AAAA` на `2606:50c0:8000::153` … `8003::153`).
2. GitHub → репозиторий → **Settings → Pages → Custom domain**: впишите домен, сохраните,
   дождитесь проверки DNS и включите **Enforce HTTPS**.
   (При деплое через Actions файл `CNAME` в репозитории не нужен — домен хранится в настройках Pages.)
3. Сайт на своём домене открывается из корня, поэтому `base` должен быть `/`:
   **Settings → Secrets and variables → Actions → Variables → New repository variable**
   `VITE_BASE` = `/`. Затем перезапустите workflow (Actions → Deploy to GitHub Pages → Run workflow)
   или сделайте любой push.

## Формат логов

```
ID <TAB> Ник [статик] <TAB> Фракция <TAB> Текст события <TAB> ДД.ММ.ГГГГ, ЧЧ:ММ:СС
```

- Дата/время — регулярным выражением с конца строки, ID — с начала, середина делится по табам или 2+ пробелам.
- Если разделители совсем потерялись (одиночные пробелы), ник выделяется по `[статик]`, а фракция — по известным названиям и алиасам.
- Перед разбором удаляются невидимые символы (U+200B, U+200C, U+200D, U+2060, U+FEFF и др.), неразрывные пробелы заменяются обычными.
- `SYSTEM [1]` — системное событие фракции, игроком не считается.
- Неразобранные строки (заголовки, «Prince — 23:50», «message.txt», «8 кб») пропускаются и считаются в «Пропущено».

## Принятые решения и допущения

- **Дизайн.** Макет Claude Design не был приложен — сделана лаконичная админ-панель (светлая/тёмная тема,
  выбор запоминается в `localStorage`, по умолчанию — как в системе).
- **Примеры логов.** Реальные файлы логов не были приложены. В `samples/sample-ballas.txt` лежит
  синтетический лог (генератор — `scripts/make-sample.ts`), покрывающий все правила, мусорные строки Discord,
  невидимый U+2060, `#65`, табы/пробелы, чужие фракции и даты. Фикстуры тестов — `tests/fixtures/` и
  генераторы строк в `tests/helpers.ts`. Когда появятся реальные логи — положите их в `samples/` и
  добавьте проверки в `tests/sample.test.ts`.
- **Поезд, «доставка 189 ящ.».** В ТЗ сказано, что доставка 189 ящ. даёт спорный случай, но порог — ≥ 125 ящ.,
  и 189 его проходит. Реализовано строго по порогу: 189 ящ. спорно только при недоборе участников
  (так и проверено в тесте). Если нужен другой порог — поменяйте `final.minNumber` у правила `train`.
- **PvP (допущение).** Группа строк «вывозит хаммер с территории и получает …» с паузами ≤ 60 мин — одно
  мероприятие; каждая строка «занимает 1 место и получает …» — отдельное мероприятие (`soloPhrases`).
  Всё вынесено в конфиг правила `pvp`.
- **ФЗ / NG.** Одна ЭМИ-строка подтверждает только одну группу выгрузок (не может превратить в ФЗ несколько атак).
  Берётся ближайшая к группе ЭМИ-строка в окне 60 минут.
- **Привязка к дню.** Группы (`cluster`/`variantCluster`) относятся к дню своей первой строки, `sequence` —
  к дню финальной строки. Окна «до» (ЭМИ за 60 мин, участники поезда за 90 мин) смотрят и в предыдущие сутки,
  если они есть в загруженных файлах.
- **Порядок строк** с одинаковым временем определяется ID строки лога (он растёт со временем), затем номером строки в файле.
- **Ганшоп.** < 1000 материалов — спорный случай «N — меньше порога 1000».
- **Секунды в дате.** Если в строке нет секунд (`ЧЧ:ММ`), считаются как `:00`.
- **Ручные достижения и корректировка** сбрасываются при смене фракции, даты или загрузке новых файлов
  (истории и экспорта по ТЗ нет). Корректировка входит в сумму до применения лимита 30.
- **Аирдроп.** Финальная строка засчитывается только от `SYSTEM [1]`.
- **Чёрный рынок / поезд / аирдроп.** Участники считаются только по строкам игроков (не SYSTEM).

## Структура

```
src/
  config/        правила и фракции (crime.ts, gov.ts, types.ts)
  lib/parser.ts  очистка и разбор строк
  lib/matcher.ts шаблоны фраз → RegExp
  lib/engine.ts  движок правил (perLine, perCount, cluster, sequence, variantCluster)
  lib/pipeline.ts загрузка файлов, фильтр фракции/даты
  worker/        Web Worker (разбор и расчёт вне UI-потока)
  components/    интерфейс
tests/           Vitest: парсер, правила, лимит, Гос, производительность, пример лога
samples/         пример лога
```
